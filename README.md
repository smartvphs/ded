# MY PART — لوحة تحكم React

## تشغيل المشروع

```sh
npm install
npm run dev
```

## تجهيز نسخة الإنتاج

```sh
npm run build
npm run preview
```

- `src/main.jsx`: شاشة لوحة التحكم.
- `src/Orders.jsx`: جدول الطلبات وأشكاله الأربعة حسب اختيار الدروب داون.
- `src/style.css`: تنسيق الواجهة العربية واتجاه RTL والتجاوب.
- `public/`: الخط والأيقونة.

البيانات تجريبية في الواجهة ولا ترتبط بخادم. الشعار وصور المنتجات بدائل تقريبية من المرجع.

## صفحات التعريفات

`src/Definitions.jsx` و`src/definitions.css` يحتويان صفحات السكشن التعريفي والسياسات وبنرات الأقسام والإعلانات والشريط الإعلاني. الإضافة والحذف والرفع والحفظ تعمل في ذاكرة المعاينة الحالية فقط؛ تتصفّر البيانات مع إعادة تحميل الصفحة. لا يوجد ربط بقاعدة بيانات أو تخزين دائم.

## طلبات التسعير

`src/Pricing.jsx` و`src/pricing.css`: قائمة طلبات التسعير والبحث والتصفية والتحديد وتصدير CSV قابل للفتح في Excel، وتفاصيل الطلب وإضافة المنتجات وتسعير القطع بجودات متعددة. جميع إجراءات الإرسال وإضافة المنتج محاكاة في المعاينة؛ لا يتم إرسال رسالة أو إنشاء سجل في خادم. البيانات والأسعار مؤقتة وتُصفّر مع إعادة تحميل الصفحة.

## الإشعارات والكوبونات والسلات المتروكة

`src/AdminPages.jsx` و`src/admin-pages.css` يحتويان صفحات الإشعارات والكوبونات مع الإضافة والتعديل والتفعيل، والسلات المتروكة وتفاصيل السلة. البيانات مؤقتة للمعاينة فقط. إرسال رسائل استرداد السلات محاكاة ولا يرسل رسائل فعلية.

## إدارة التصنيفات

كل كارت في التصنيفات الرئيسية يفتح إدارة القسم الخاص به. `CategoryManager.jsx` لإدارة شركات السيارات والموديلات وتصنيفات القطع، وماركات الزيوت وأنواعها ولزوجتها، وماركات الإطارات والمقاسات والتصنيع، وشجرة تصنيفات الخدمات، والإكسسوارات والتوافق والتركيب. `CategoryAnalytics.jsx` لتبويب إحصائيات قطع الغيار. جميع التعديلات بيانات معاينة مؤقتة غير مرتبطة بخادم، والصور غير المقدمة بدائل مؤقتة.

## الموظفون والصلاحيات

`src/Employees.jsx` و`src/employees.css` يحتويان قائمة الموظفين ونموذج الإضافة وصفحة صلاحيات كل موظف للقراءة والكتابة والحذف، وصلاحيات فرعية للتصنيفات والعملاء. إعدادات الصلاحيات للمعاينة فقط ولا تطبق تحكم وصول على الخادم.

## العملاء

`src/Customers.jsx` و`src/customers.css`: إدارة العملاء والتفاصيل والإضافة والتعديل والبحث، ورصيد المعاينة ونسبة الكاش باك، والمركبات والطلبات والتسعيرات والسلة والعناوين. تعديل الرصيد والحظر والتنبيه محاكاة مؤقتة ولا يحدث معاملات أو إرسالًا فعليًا.

## تذاكر المساعدة

`src/Support.jsx` و`src/support.css`: قائمة التذاكر والبحث والتصفية والحالة والتعيين والمحادثة والملاحظات الداخلية والإجراءات السريعة، وإدارة أنواع المشكلات. الرسائل والتعيين والإغلاق محاكاة مؤقتة في المعاينة ولا يتم إرسال رسائل فعلية. المرفقات بيانات تجريبية لأن ملفاتها الأصلية لم تُقدّم.

## تسجيل الدخول وOTP

`src/Login.jsx` يحتوي على صفحة البريد وكلمة المرور ثم صفحة OTP.
`src/auth-api.js` يرسل POST إلى:

- https://car-parts-backend.vercel.app/api/admin/login: `{email,password}`
- https://car-parts-backend.vercel.app/api/admin/login/verify: `{challengeId,code}`

يُقرأ challengeId من المستوى الأعلى أو data. لا تُفتح لوحة التحكم إلا بعد نجاح verify. يدعم التوكن داخل token أو accessToken أو data، أو تأكيد success/authenticated. تُحفظ الجلسة بعد تحقق OTP في localStorage تحت mypart.admin.session.v1، دون حفظ كلمة المرور أو رمز التحقق. تستمر بعد إعادة التحميل وإعادة فتح المتصفح، ويُحفظ refreshToken الجديد بعد تجديده. تسجيل الخروج يمسح الجلسة محليًا فورًا ويطلب إبطال refreshToken عبر /api/auth/logout؛ يبقى الخروج المحلي ناجحًا إذا كان الاتصال غير متاح.

وفقًا لملف Admin API، يعتمد تسجيل الدخول على accessToken وrefreshToken في استجابة JSON، وتستخدم الطلبات المحمية Bearer Token. تستخدم طلبات الدخول والتحقق وإعادة الإرسال credentials: omit دون إرسال كوكيز، لتتوافق مع Access-Control-Allow-Origin: *. اختُبر مسار الدخول وOTP باستجابات محاكاة؛ تعذر اختبار الخادم الحقيقي من بيئة التنفيذ بسبب قيود الشبكة. ما زالت بقية عمليات إدارة البيانات معاينة محلية وليست مرتبطة بواجهات الخادم.

إعادة إرسال OTP: POST /api/admin/login/resend مع {challengeId}. تُحدّث بيانات التحدي والصلاحية والانتظار والمحاولات من استجابة الخادم. عند غياب وقت الانتظار يستخدم زر الإرسال مهلة واجهة احتياطية مدتها 60 ثانية، ويظل الخادم مسؤولًا عن التحقق والحدود.


## ربط الصفحة الرئيسية بواجهات Admin API

- `src/Dashboard.jsx`: بيانات البانر، بطاقات الإحصائيات، توزيع حالات الطلبات، الإيرادات والتسعير، المنتجات والموردون والنشاطات من `GET /api/admin/dashboard`. لا تستخدم الهوم أرقام المعاينة القديمة.
- الفترات آخر 7 / 30 / 365 يومًا، بالأيام الشاملة في توقيت السعودية. تغيير الفترة يحدّث أقسام التقرير معًا؛ ملخص الشهر والعدادات الحية يظلان وفق تعريف الخادم. رسم التسعير يجمع الفترات اليومية إلى أشهر.
- الإحصائيات إجمالية لجميع الأقسام؛ مسار Dashboard الموثّق لا يقبل فلتر قسم. فلتر الأقسام يخص جدول الطلبات فقط.
- `src/DashboardOrders.jsx`: طلبات التسعير عبر `/api/pricing-requests/admin` بفلاتر `statuses` أو `hasAccepted`، وآخر طلبات الشراء عبر `/api/orders/all`، مع صفحات من 5 سجلات وتفاصيل فعلية. المستعمل والإكسسوارات يعرضان طلبات الشراء فقط؛ توثيق فلتر التسعيرات يدعم part/tire/oil/service.
- إلغاء الطلب ليس حذفًا محليًا: يستخدم مسار الإلغاء الفعلي أو تحديث حالة طلب الشراء إلى cancelled، بعد تأكيد المستخدم. تأكيد الطلب pending يستخدم PATCH لحالته؛ الخادم يفرض الصلاحيات وحالة الدفع. استرداد المدفوعات لا يُنفذ تلقائيًا من الواجهة.
- `src/admin-api.js`: يرسل Bearer accessToken دون كوكيز. تجديد الجلسة يستخدم `/api/admin/refresh` مرة واحدة عند 401 مع توحيد طلبات التجديد المتزامنة. التوكنان محفوظان في localStorage بعد نجاح OTP، وتُزامن الجلسة والخروج بين التبويبات. يستخدم Web Locks حيثما توفّر لتنسيق تدوير refreshToken بين التبويبات.
- تُخفى بطاقة الزوار عندما يكون `visitors.isActive` غير مفعّل، ويُذكر العداد اليدوي والربح الجزئي أو التقديري كما يحدده الخادم. الصفر يُعرض عند وروده، والقيم المفقودة تظهر بشرطة.
- توجد حالات تحميل وبيانات فارغة وأخطاء وصلاحيات وإعادة محاولة، وتُلغى الطلبات القديمة عند تغيير الفلاتر.

التحقق: `npm ci` ثم `npm run build`، و`node --test tests/dashboard.test.mjs`. اختُبر تدفق الواجهة في Chromium باستجابات محاكاة مبنية على ملف Postman (الدخول وOTP، الفلاتر، التفاصيل والإجراءات، التجديد، الأخطاء والموبايل). لم يُختبر حساب فعلي بسبب حجب اتصال الخادم من بيئة التنفيذ. صفحات الإدارة الأخرى تظل معاينة محلية حتى ربطها.


## واجهات الطلبات والإرجاعات

`OrdersPage.jsx` و`OrderDetail.jsx` و`orders-page.css` تنفذ القائمة والإحصائيات والبحث والتحديد والصفحات، تفاصيل الطلب وتبويبات الشحن والتكاليف والفاتورة، نموذج تعديل/إضافة المنتجات، وقائمة الإرجاع والتفاصيل حسب المراجع العشرة المرفقة. القائمة والتفاصيل والفاتورة والإرجاعات مرتبطة بالمسارات الموثقة. البحث والتاريخ والحالة وتصفية الاسترجاع تُرسل للخادم. فلاتر المورد/الشركة/الدفع/المصدر تعمل على نتائج الصفحة الحالية، ويظهر ذلك عند استخدامها.

الحفظ الفعلي للطلب يقتصر على status وtrackingNo وadminNotes وshippingCompanyId وفق PATCH /api/orders/:orderId/status. تعديل المنتجات والعنوان والتواصل والدفع والتكاليف، وإنشاء الطلبات الجديدة، مسودات معاينة في الذاكرة فقط؛ لا توجد مسارات موثقة لحفظها في ملف Postman المرفق. مراجعة الإرجاع تستخدم PATCH /api/returns/admin/:returnId. لا تُنفذ إجراءات مدفوعات أو استرداد تلقائيًا. زر تحميل PDF يفتح الطباعة لحفظ الفاتورة كـPDF، وزر الإرسال ينسخ ملخصها للمشاركة اليدوية.

اختبارات الجلسة والبيانات: `node --test tests/*.test.mjs`. اختُبرت الشاشات والتفاعلات في Chromium باستجابات Postman محاكاة، بما فيها بقاء الجلسة بعد reload وفي تبويب جديد وتجديدها ومسحها عند الخروج، وفُحص عرض سطح المكتب والموبايل. قد يلزم الدخول مرة واحدة بعد أول تحديث ينقل الجلسة من الذاكرة إلى التخزين الدائم.

## ربط صفحة المنتجات — تحديث Postman (3)

`ProductEditor.jsx` يقرأ تفاصيل المنتج من مسار الإدارة، وينشئ منتجًا باسم المنصة عبر `POST /api/products/admin` بدون مورد، أو لمورد معتمد اختياريًا عبر `POST /api/products/admin/:supplierId`. الحفظ الفعلي يشمل الأسماء والأرقام البديلة والتكلفة والأسعار والمخزون والتصنيفات والماركة والمواصفات والشحن المجاني والعرض الخاص. السعر الأساسي يُقرأ من `oldPrice` عند وجود سعر مخفض. رفع الصور موقّع، حتى 5 ميجابايت؛ استبدال الصور والمواصفات يستخدم العلمين الموثقين، وتوافق السيارات وحالة النشر يستخدمان مساريهما. تظهر نتيجة الحفظ بعد إعادة الجلب، وفشل خطوة لاحقة يحافظ على المسودة ويبيّن ما لم يكتمل؛ نتيجة الإنشاء المجهولة تمنع إعادة إنشاء تلقائية.

`ProductExtras.jsx` يربط المنتجات المرتبطة (بحث وإضافة وإزالة ثم حفظ القائمة ذريًا)، والتقييمات وإحصائياتها وإخفائها وحذفها. إضافة تقييم تتطلب رقم طلب يحتوي على المنتج، واسم العميل من الطلب وليس إدخالًا حرًا. الجودات الأخرى تُنشأ تحت نفس رقم القطعة، وتُعدّل أسعارها وإتاحتها بمسارات المنتج الخاصة برقم الجودة. أحجام العبوات لها إنشاء وتعديل وحذف فعلي. حالات إنشاء غير مؤكدة تمنع إعادة الإضافة حتى إعادة جلب القائمة. آخر التسعيرات تُقرأ من مسارها؛ توليد الوصف لا يحفظه تلقائيًا، ويعرض أخطاء 503 بدل وصف بديل مصطنع.

`ProductImport.jsx` يدعم الاستيراد باسم المنصة أو لمورد مختار، مع القالب، فحص الملف، دفعات 100، نتائج كل صف، ومنع إعادة استيراد نتيجة مجهولة. `product-export.js` يجلب كل النتائج المطابقة للفلاتر بدون paging عبر مسار export وصلاحية data.export؛ ينشئ جدولًا عربيًا آمنًا باستخدام textContent في نافذة الطباعة ليُحفظ PDF. فشل الصلاحيات لا يتحول إلى طباعة الصفحة الحالية.

`ServiceProducts.jsx` يفصل طلبات الخدمات عن الكتالوج. جدول العملاء يأتي من `GET /api/orders/all?source=service`، وتفاصيله من `/api/orders/admin/:orderId` للسيارة والخدمة والمركز. تبويب الكتالوج يأتي من `/api/suppliers/admin/services`. `ServiceEditor.jsx` ينشئ خدمة منصة ويحدّث الخدمة عبر PATCH الخاص بالخدمات، دون إرسالها إلى مسار المنتج ودون تغيير حالة المراجعة تلقائيًا. لا توجد أسماء أو صور عملاء مستنتجة من بيانات الخدمة.

قراءة المواصفات تدعم المفاتيح القديمة والجديدة، وتُظهر التعارض بدل اختيار قيمة عشوائية؛ تعديل حقل يزيل تكرارات مرادفاته فقط ويحفظ باقي المواصفات. تفاصيل صفوف المنتجات تظهر تدريجيًا، ولا يمنع طلب بطيء عرض باقي الصفوف.

التحقق: `node --test tests/*.test.mjs`، و`PLAYWRIGHT_MODULE=/path/to/playwright-core node tests/product-new-api-browser.cjs` مع Vite على 5182 (أو TEST_BASE_URL). اختبارات المتصفح تستعمل استجابات محاكاة لعقود Postman تشمل الإضافة والحفظ والأخطاء وإعادة المحاولة والمنتجات المرتبطة والتقييمات والعبوات والجودات والتصدير والاستيراد والخدمات والموبايل. لا تنشئ بيانات اختبار على الخادم الحقيقي.
