# تفعيل التذاكر والتكاليف داخل التصميم الحالي

## التذاكر

تم تفعيل قائمة تعيين الموظف الموجودة وأزرار الأولوية والملاحظات الداخلية والحذف. الأزرار تفتح نوافذ من نفس مكونات التصميم الحالية؛ لم يُضف قسم إدارة جديد. تفاصيل المورد تستخدم نفس المنطق: خانة الملاحظة الداخلية تفتح نافذة الملاحظات، والإجراءات السريعة تظل في مكانها وبنفس ألوانها وأيقوناتها، مع تعيين الموظف داخل نفس القسم.

- GET assignees للقائمة الرسمية؛ PATCH assign يدعم staffId:null لإلغاء التعيين.
- PATCH priority لاختيار الأولوية؛ زر الرفع يقترح urgent مع إمكانية الاختيار قبل التأكيد.
- POST notes للملاحظات الإدارية فقط، وDELETE notes للمؤلف أو المشرف العام. الرسالة الداخلية لا تُرسل عبر مسار reply، ولا يتم تغيير حالة التذكرة بسببها.
- DELETE ticket بعد تأكيد، ثم GET يجب أن يرجع 404 قبل إعلان الحذف وتحديث القائمة.
- يتم التحقق من الكتابة بقراءة التفاصيل، والنتائج المحفوظة تُراجع بالقراءة فقط عند فشل التحميل. الملاحظة ذات نتيجة الإرسال غير المؤكدة لا يعاد POST لها؛ يمكن تأكيدها من معرفها أو من ملاحظة جديدة مطابقة تخص الكاتب ولم تكن موجودة قبل الإرسال.
- الحالات والأولوية والرد والمرفقات الموجودة مستمرة، مع تعطيل الإجراءات المتعارضة أثناء الطلب والصلاحيات من GET /api/admin/me.

## التكاليف

جدول تكاليف الطلب يحتفظ بأعمدته السبعة. الضغط على قيمة التكلفة، أو «تسجيل التكلفة» في نفس الخانة الفارغة، يفتح تعديل تكلفة الوحدة. لا يوجد عمود إجراءات إضافي.

- PATCH /api/orders/admin/:orderId/items/:itemId/cost يدعم الصفر، وملاحظة محاسبية، وunitCost:null لإزالة التكلفة اليدوية.
- تأكيد مصدر manual وقيمة الوحدة والملاحظة بالقراءة من /costs، أو تأكيد زوال المصدر اليدوي عند الإزالة.
- حسابات orders.manage فقط تعدل؛ بنود الخدمات لا تعرض محرر التكلفة اليدوية لأنها تتحدد بإسناد الخدمة.
- لا يتغير إجمالي ما دفعه العميل، ولا تُرسل إشعارات.

تقرير الأرباح يحتفظ بالكروت والجداول نفسها. زر «مراجعة التكاليف الناقصة» داخل التنبيه الموجود يفتح قائمة من GET /api/admin/reports/missing-costs بنفس الفترة السعودية وترقيم صفحات السيرفر. حفظ تكلفة بند يحدث القائمة والتقرير؛ لا يُضاف جدول دائم للصفحة. قائمة القراءة متاحة حسب صلاحيات التقارير، والتعديل يتطلب orders.manage.

## التحقق

83 اختبار كود ناجح، وبناء إنتاج ناجح. اختبارات Chromium تشمل التذاكر العامة وتذاكر المورد، التعيين وإلغاءه والأولوية، الملاحظات وعدم إرسالها عبر الرد، حذف ملاحظات الكاتب، تأكيد حذف التذكرة، الصفر وإزالة التكلفة، إعادة التحقق دون تكرار الكتابة حتى بعد إغلاق النافذة وفتحها، حماية الخدمة والحساب القارئ، فترة قائمة التكاليف وتحديثها. اختبارات التذاكر والطلب والتقرير الحالية نجحت أيضًا، مع فحص الموبايل وعدم وجود أخطاء JavaScript.

لم يتم إرسال ردود أو إشعارات أو تعديل تكاليف أو حذف تذاكر على السيرفر الحقيقي أثناء الاختبار؛ جميع الكتابات في الاختبارات ردود API محاكية.
